# Крок 08 — Стабілізація тестів і CI

**Статус: ⬜ не розпочато** (hotfix-частину можна виконати будь-коли, поза чергою) · Залежності: кроки 03–04 (їхні тести входять у пас)
**Вхідні дані:** [general_alpha_2_0.md](general_alpha_2_0.md) (крок 08), лог першого push (CI впав на analyze), рев'ю alpha 1.0 (ризики №1 і №3)

## Мета

CI зелений, швидкий і чесний: analyze проходить, тестовий крок не зависає, три «прокляті» widget-тести або полагоджені, або ізольовані з задокументованою причиною. Технічний борг з код-рев'ю кроку 02 (у межах, дозволених власником) погашено.

## Контекст

- **CI червоний на analyze:** pubspec декларував `assets/images/characters/`, `assets/images/ui/`, `assets/fonts/`, які були порожні й не потрапляли в git → 3 warnings `asset_directory_does_not_exist` → exit 1. **Стан змінився (2026-07-05):** теки наповнені (шрифт GeistPixel у `fonts/`, `.gitkeep` у `characters/` та `ui/icons/`) — але нові асети ще не закомічені, і з'явилась нова прогалина: під-теки `assets/images/` (плоскі PNG, `hacker/`, `icons/`) та `assets/audio/` (`background_tracks/`, `sound_effects/`) **не декларовані в pubspec** — Flutter не бере asset-теки рекурсивно, тож нічого з нового не потрапить у білд.
- **Тестовий крок CI ще жодного разу не виконувався** (падає раніше) — ризик №1 рев'ю (зависання `flutter test`) досі не перевірений.
- **3 зависаючі widget-тести:** `economy_widgets_test.dart`, `target_board_widgets_test.dart`, `profile_widget_test.dart` — комбінація реальної файлової БД + ConsumerWidget + ProviderContainer; підозра на конфлікт двох Flutter SDK (`C:\Development\flutter` і `C:\flutter_SDK\flutter`).
- **CI-конфіг** ([ci.yml](../../../.github/workflows/ci.yml)): `flutter test` без виключень і **без `timeout-minutes`** — зависання висітиме до 6-годинного ліміту GitHub.
- **Борг код-рев'ю кроку 02** (04.07.2026, 10 знахідок): критичні по логіці цілей відкладені власником на майбутні версії; сюди входить лишок, що не стосується логіки цілей.

### 8.5 Борг код-рев'ю кроку 02 (без логіки цілей)

- [ ] **Симулятор чесний:** сценарій «банкрут» у `tool/simulate.dart` викликає реальні чисті функції/формули замість власних копій: ціна продажу — зі спільної quote-функції (див. нижче), перевірка останнього софту — не `if (1 <= 1) throw`-театр; фінальний критерій успіху вимірює **результат відновлення** (успішна атака страхового контракту), а не баланс, що вже поповнений продажем.
- [ ] Жорстку перевірку `levelReachedAt[2]==5 && levelReachedAt[5]==15` виконувати лише при дефолтному attackCount (≥15) — `simulate.dart 10` не має падати.
- [ ] **Дедуплікація EconomyTuning:** `static const EconomyTuning.defaults` + один спільний loader (`EconomyTuning.load(DatabaseExecutor)`) замість 6 копій літерала та 4 копій `query meta + jsonDecode`.
- [ ] **Єдина формула ціни продажу:** pure static `InventoryRepository.softwareSellPrice(...)`/`hardwareSellPrice(...)` — використовується і транзакцією, і Workshop-екраном, і симулятором (зникає ризик «діалог цитує одну суму, транзакція платить іншу»).
- [ ] *Не чіпати* (рішення власника, alpha 3.0+): honeypot×страховий слот, floor на індексі 0, free-scan із loading-стану, side-effect у activeContractsProvider, expiry у fetchContractDetails. Перенести ці 5 пунктів списком у `docs/planning/alpha_3_0/backlog.md` (створити файл), щоб не загубились.
