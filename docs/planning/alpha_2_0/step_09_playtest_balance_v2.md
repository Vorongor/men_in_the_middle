# Крок 09 — Живий плейтест і баланс v2

**Статус: ⬜ не розпочато** · Залежності: кроки 01–08 (тестерам іде повністю зібрана версія) · Частину 9.1–9.2 можна почати одразу після 03
**Вхідні дані:** [general_alpha_2_0.md](general_alpha_2_0.md) (крок 09), рев'ю alpha 1.0 (ризики №2 і №4 — жодного запуску на фізичному Android; «фан» тримається на одній міні-грі)

## Мета

Відповісти на головне питання проєкту руками живих людей: **чи цікаво грати в «Перехоплення потоку» вдесяте поспіль** — і за результатами відкалібрувати баланс правками лише в JSON. Верифікувати збірку на фізичному Android, чого не було зроблено за весь alpha 1.0.

## Задачі

### 9.1 Підготовка

- [ ] Зібрати роздавальні білди: release APK + Windows zip (поточна гілка з кроками 01–08).
- [ ] Інструкція тестера (`docs/planning/alpha_2_0/tester_guide.md`, 1 сторінка): що це за гра, як встановити APK з невідомого джерела, скільки грати (30–40 хв), куди писати фідбек.
- [ ] Анкета фідбеку (у тому ж файлі, 8–10 питань): «чи зрозуміли, що робити, без пояснень?», «міні-гра на 10-й раз — цікаво/терпимо/нудно?», «чи застрягали ви без грошей/місій?», «що дратувало найбільше?», «розмір завантаження — проблема?», «скільки хвилин грали б ще?».

### 9.2 Власний smoke на фізичному Android (ризик №2 рев'ю)

- [ ] Встановлення APK на реальний пристрій; холодний старт (splash, час запуску).
- [ ] Реєстрація → 3 повні атаки (з міні-грою) → покупка → апгрейд → продаж → emergency scan.
- [ ] Окремо перевірити: продуктивність відео-фону media_kit (нагрів/лаги), тач-керування паддлом (зручність пальцем — головна невідомість Sniffer), поворот/згортання застосунку посеред міні-гри.
- [ ] Результат — у Summary кроку; блокери → фікси до роздачі тестерам.

### 9.3 Роздача і збір фідбеку

- [ ] 2–3 тестери з Android-пристроями; дедлайн фідбеку — 3–5 днів.
- [ ] Зібрати відповіді у `docs/planning/alpha_2_0/alpha_2_0_playtest_notes.md`: сирі нотатки + зведення по темах (фан міні-гри / зрозумілість / економіка / баги / розмір).
- [ ] Нові баги — одразу в реєстр (розширити таблицю в general-плані), з пріоритетами; критичні фіксити до кроку 10.

### 9.4 Баланс v2 (лише JSON)

- [ ] За фідбеком і нотатками виправити числа в `assets/data/catalog/*.json` (ціни, нагороди, криву рівнів, sell_ratio/fee в economy.json, складність SnifferConfig-скейлінгу через defense цілей).
- [ ] Кожну ітерацію проганяти через `dart run tool/simulate.dart` (після чесного bankrupt-сценарію з кроку 08): банкрутство відновлюване, прогресія в межах цілей. Якщо цілі прогресії свідомо зсуваються — оновити перевірку в симуляторі й зафіксувати нові цілі в цьому файлі.
- [ ] Bump `ContentSeeder.currentContentVersion` для перезаливки каталогів у тестерів.

### 9.5 Рішення за результатами (зафіксувати в Summary)

- [ ] **Стретч «Дешифратор»:** робити прототип другої міні-гри лише якщо (а) всі баги плейтесту закриті, (б) фідбек по Sniffer позитивний. Інакше — перенести в alpha 3.0 backlog з обґрунтуванням.
- [ ] **Відео-фон/вага APK:** якщо ≥ половини тестерів назвали розмір проблемою — заміна на шейдер планується в кроці 10 або alpha 3.0 (заміри вже є з кроку 07.5).

## Критерії приймання

- [ ] Smoke-пас на фізичному Android пройдено, результати задокументовані (закриває пункт Definition of Alpha, що висів з alpha 1.0).
- [ ] Фідбек ≥ 2 тестерів зібрано і зведено в playtest_notes.
- [ ] Баланс v2 закомічено лише як зміни JSON (+ верифікація симулятором); жодних балансних чисел у Dart-коді.
- [ ] Обидва рішення (Дешифратор, відео-фон) ухвалені та записані.
