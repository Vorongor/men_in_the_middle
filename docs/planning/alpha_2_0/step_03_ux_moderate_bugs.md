# Крок 03 — Помірні UX-баги: снекбари, Workshop, Settings з гри

**Статус: ⬜ не розпочато** · Залежності: кроки 01–02 (✅) · Баги тест-звіту: **№3, №4, №5 (помірні)**
**Вхідні дані:** [alpha_1_0_test_summary.md](alpha_1_0_test_summary.md), [general_alpha_2_0.md](general_alpha_2_0.md) (крок 03)

## Мета

Прибрати три постійні UX-подразники: повідомлення більше не перекривають кнопки, апгрейд у Workshop не викидає гравця з екрана предмета, налаштування доступні зсередини гри без виходу в головне меню.

## Контекст (з коду)

- **№3.** У `lib/` — 14 викликів `showSnackBar` у 5 екранах (`workshop_item_screen` ×5, `target_board_screen` ×4, `store_item_screen` ×2, `market_item_screen` ×2, `login_screen` ×1), кожен зі своїм інлайновим стилем. Усі — дефолтні `fixed`-снекбари: розтягуються на всю ширину внизу і візуально накривають нижні CTA-кнопки (LAUNCH ATTACK, REFRESH, UPGRADE/SELL) до зникнення.
- **№4.** [workshop_item_screen.dart](../../../lib/screens/workshop_item_screen.dart): `_handleUpgrade` після успіху викликає `Navigator.pop(context)` — гравця викидає на список Workshop. Причина архітектурна: `FutureBuilder` створює future прямо в `build`, тож екран не вміє «оновитись на місці» (це ж породжує зайві refetch-и — див. знахідку код-рев'ю).
- **№5.** `home_page_screen.dart` не містить жодного входу в Settings; роут `/settings` існує і працює (Screen 1.2), збереження — shared_preferences.

## Задачі

### 3.1 Єдиний хелпер снекбарів (баг №3)

- [ ] Створити `lib/widgets/app_snack.dart`: `showAppSnack(BuildContext, String message, {AppSnackKind kind = info})`, kind ∈ {success, error, info} задає кольори (поки поточні #0C160C/#240C0C, з кроку 05 — токени).
- [ ] Поведінка, що розв'язує баг: `SnackBarBehavior.floating` + `margin` знизу (~80, щоб плавати НАД нижньою CTA-кнопкою), `duration: 2s` (замість дефолтних 4с), `dismissDirection: down`, і `clearSnackBars()` перед показом — повідомлення не стають у чергу одне за одним.
- [ ] Мігрувати всі 14 викликів на хелпер; заборона прямого `ScaffoldMessenger.of(context).showSnackBar` поза хелпером (перевірити grep-ом у критеріях приймання).
- [ ] Для повідомлень-підтверджень дії, після якої гравець і так бачить результат (успішний апгрейд/продаж — цифри оновились), розглянути скорочення до 1.5s або взагалі прибрати текст — рішення зафіксувати в коді коментарем.

### 3.2 Workshop: апгрейд лишає на екрані (баг №4)

- [ ] Прибрати `Navigator.pop` з `_handleUpgrade`; після успіху екран оновлює дані предмета на місці.
- [ ] Механіка оновлення: замінити «future у build» на кероване завантаження — мінімально: зберігати future у state і перевстановлювати його в `setState` після апгрейду; правильніше (рекомендовано): `FutureProvider.family<Owned…, WorkshopItemArgs>` + `ref.invalidate` після мутації. Це заразом прибирає повторні fetch-и на кожен rebuild (знахідка код-рев'ю по цьому екрану).
- [ ] Продаж (крок 02) **лишає** `pop` — предмета більше немає, це свідомий виняток.
- [ ] Після досягнення MAX LEVEL кнопка коректно деактивується без виходу з екрана.

### 3.3 Settings зсередини гри (баг №5)

- [ ] Додати іконку Settings (⚙) у шапку `GameScaffold` (спільний віджет усіх ігрових екранів — одна зміна дає доступ звідусіль) з `Navigator.pushNamed(Routes.settings)`.
- [ ] Виняток: на Screen 7.2 (активна атака) іконку не показувати — вихід з міні-гри йде через наявний ABORT-флоу; параметр `showSettings: false` у GameScaffold.
- [ ] Перевірити повернення: гучність BGM/SFX застосовується одразу (SettingsScreen уже зберігає на Back), сесія гравця не губиться, стек навігації повертає на той самий екран.

### 3.4 Тести

- [ ] Widget-тест: після успішного апгрейду екран Workshop Item досі показує той самий предмет з новим рівнем (регрес бага №4).
- [ ] Widget-тест хелпера: снекбар floating, не перекриває віджет під ним (перевірка geometry), другий виклик прибирає перший.
- [ ] Widget-тест: GameScaffold рендерить іконку Settings і не рендерить її при `showSettings: false`.

## Критерії приймання

- [ ] На екранах з нижніми кнопками повідомлення видно, але кнопка залишається видимою і натискається одразу (ручна перевірка Target Board + Workshop Item).
- [ ] `grep -r "showSnackBar" lib/` знаходить його лише всередині `app_snack.dart`.
- [ ] Апгрейд предмета 2 рази поспіль — гравець жодного разу не покинув екран предмета.
- [ ] З будь-якого ігрового екрана (крім 7.2) можна відкрити Settings і повернутися назад.
- [ ] `flutter analyze` — 0 issues; тести без регресій.
