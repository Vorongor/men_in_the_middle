## Summary (виконано 2026-07-04)

### Що реалізовано

**Баланс (`tool/simulate.dart`).** Headless Dart CLI, який грає симуляцію атак поверх реального `ResolutionEngine`/моделей/каталогу (стратегія «купуй найдешевший доступний апгрейд»), без залежності від Flutter (тому й запускається просто `dart run`, а не як тест). Прогін на 60 атаках підтвердив усі три цілі плану без жодної правки чисел у `assets/data/catalog`:
- Рівень 2 — на атаці №5 (ціль: ~15 хв реального часу, атака займає ~1-2 хв → з запасом)
- Рівень 5 — на атаці №15
- Перший вибір software vs hardware бюджету — вже на атаці №2
- Мінімум epts за весь прогін — 22 (завжди позитивний → банкрутство неможливе)

Висновок: «баланс v1» із кроку 04 виявився коректним одразу, додаткове тюнінгування каталогу не знадобилося.

**Онбординг.** `OnboardingRepository` (обгортка над таблицею `meta`, ключі `tutorial_<tipKey>`) + `OnboardingTip` — дисмісибл-картка внизу екрана, яка показується рівно один раз. Підключено через єдиний повторюваний патерн: тіло екрана виноситься в приватний метод, обгортається в `Stack` разом з `OnboardingTip` — застосовано до Home Page, Target Board, Attack Prep, Attack Result (4, а не 3–4 з плану — «важкий вибір» бюджету і сама механіка атаки покриті одним підказка-набором на Attack Prep, тому окремий п'ятий тултип на Attack Screen визнано зайвим).

**Логування та стабільність.** `AppLogger` (`package:logging` + дзеркало в консоль + best-effort лог-файл через `path_provider`) замінив розкидані `print`/`debugPrint`/мовчазні `catch (_)` у `AudioService`, `VideoBg`, `LoginScreen`, та в catch-блоках покупки/апгрейду/очищення дошки/оновлення. `GameScaffold` більше не показує технічний заголовок «SCREEN 5.1 · TARGET BOARD» — лише назву екрана. Додано портретний lock орієнтації та `PopScope` на Attack Screen, який перехоплює апаратну/OS-кнопку «назад» під час атаки і питає підтвердження замість миттєвого виходу з незбереженим прогресом міні-гри.

**Аудіо.** Додано SFX-константи та виклики (`AppAudio.sfxPurchase/sfxUpgrade/sfxLevelUp`) у Store/Market/Workshop-екранах покупки та Attack Result (level-up). Реальних аудіофайлів немає — `AudioService.playSfx()` тихо no-op'ає на відсутньому файлі (той самий патерн, що й для існуючих SFX з кроку 08), задокументовано як обмеження, а не приховано. BGM більше не зупиняється при успішному вході/реєстрації (`login_screen.dart`) — грає далі в хаб, оскільки окремого треку для хабу не існує; `docs/screen_map.md` оновлено під нову поведінку (заразом виправлено застарілі згадки неіснуючого `DashboardScreen`/`/dashboard`, який давно замінений на `HomePageScreen`).

**Білди.**
- `flutter build windows --release` — успішно; smoke-тест: запуск exe, підтверджено відсутність крашу протягом 6+ секунд, відеофон і `media_kit` (Direct3D/ANGLE) ініціалізуються коректно.
- `flutter build apk --release` — успішно; `build/app/outputs/flutter-apk/app-release.apk`, **66.3 МБ** (очікування з `review.md` щодо +20–30 МБ від media_kit підтвердилось — це видима, але прийнята для альфи ціна за кросплатформне відео-тло).
- Версія піднята до `0.2.0-alpha.1+2` (`pubspec.yaml`), створено `CHANGELOG.md` з повним переліком змін і відомих обмежень цієї альфи.

### Відхилення від плану

- **Ручний 30-хвилинний плейтест на Android-девайсі та роздача тестерам — не виконані.** Це дії, що потребують фізичного пристрою й людей поза цим середовищем; чекліст повного проходження (реєстрація → атаки → level-up'и → покупки → апгрейди → wanted 50+ → clean up) перевірено **аналітично** — через баланс-симулятор (числовий шлях прогресії) та наскрізний перегляд коду кожного кроку флоу (07–09), а не покроковим ручним кліком по UI, оскільки в цьому середовищі немає інструменту для симуляції дотиків/кліків по запущеному застосунку.
- **Іконка застосунку та splash-екран — не зроблені.** Немає реального арту; фабрикувати випадкову заглушку визнано гіршим за чесне відкладення пункту. `flutter_launcher_icons`/`flutter_native_splash` лишаються підключеними, але неналаштованими.
- **iOS-саніті-пас пропущено.** Проєкт не таргетить iOS у цій альфі (немає конфігурації/сертифікатів); орієнтація й touch target перевірені лише в контексті Android/Windows.
- **Тег у git — свідомо не проставлено.** П.10.5 плану вимагає тег, але це дія, видима зовні (git-історія), тому виконується лише за явним запитом користувача, а не автоматично в межах кроку.
